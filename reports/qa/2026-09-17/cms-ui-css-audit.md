# CMS UI / CSS 审计报告

审计日期：2026-09-17  
审计范围：Admin CMS 的草稿列表、新建内容、内容编辑器、审核队列、已发布列表与详情、站点单例编辑入口  
审计方式：Chrome 纯 GUI 操作 + 1280/1440/768/390 px 响应式检查 + Vue/CSS 源码静态核对  
结论性质：只读审计；本轮未修改 CMS 源码、未提交表单、未触发发布或复制操作

## 总结

CMS 的基础视觉方向是成立的：AIRTEKPOWER 蓝、绿、深墨色在导航、按钮、状态色上的使用一致，面板、圆角、留白和主次操作也形成了稳定的工业后台风格。1440 px 桌面宽度下，编辑器的目录、正文、检查器三栏结构清晰。

当前不宜判定为“UI 已完成”。本轮确认 3 个高优先级、7 个中优先级和 2 个低优先级问题。最关键的不是单纯美观，而是：列表只取前 100 条、站点配置页在访问时隐式创建草稿、已发布详情只是原始 JSON、所谓本地预览不呈现真实内容，以及响应式 CSS 与当前组件类名已经脱节。

## 正向观察

- 颜色 token 与 AIRTEKPOWER 的蓝、绿、深墨色视觉体系一致，主按钮和导航选中态辨识度好。
- 1440 px 下编辑器三栏关系明确；目录、编辑区、SEO/区块检查器的职责容易理解。
- 页面标题、说明和主要操作通常有清楚的层级；新建内容的三步流程也比一次性长表单更易用。
- 实际浏览过程中未发现控制台 error 或 warning。
- 已检查界面没有横向溢出；390 px 下页面仍能收进视口。

## 问题清单

### CMS-UI-001 — 已发布与审核列表超过 100 条后不可达

- 严重度：High
- 类型：Functional / UI
- 位置：`/content/published`、`/content/reviews`
- 证据：`PublishedContentView.vue:12-15` 和 `ContentReviewsView.vue:14-18` 固定请求 `limit: 100`，页面没有游标、分页、总数、搜索或筛选。
- 影响：第 101 条以后的内容或审核任务在 GUI 中完全不可见，用户也无法判断是否还有更多记录。
- 建议：复用草稿列表的服务端分页模式；显示总数、上一页/下一页，并为已发布内容增加标题/slug 搜索。

### CMS-UI-002 — 打开站点单例页会隐式创建私人草稿

- 严重度：High
- 类型：Functional / Auditability
- 位置：`/site/general-information`、Navigation、Footer 等单例入口
- 证据：`SiteSingletonView.vue:48-56` 先在前 100 条草稿和前 100 条已发布记录中客户端查找；如果仅找到已发布记录，页面加载阶段直接调用 `copyPublished()`。
- 影响：用户只是访问页面就会产生数据库写入、私人草稿和审计事件；同时记录位于第 101 条以后时可能被错误判定为“尚未初始化”。
- 建议：后端提供按 kind 获取单例当前状态的专用查询；先显示只读已发布状态，再由明确按钮“创建编辑草稿”执行复制。

### CMS-UI-003 — 已发布详情不是可用的内容视图

- 严重度：High
- 类型：Invalid design / UX
- 位置：`/content/published/:contentId`
- 证据：实际 UI 显示一段格式化 JSON；源码 `PublishedContentDetailView.vue:35-38` 直接渲染 `JSON.stringify(record.document.composition)`。
- 影响：编辑、审核和运营人员无法快速确认页面结构、文本和媒体，只能阅读内部数据结构。
- 建议：使用与编辑器一致的只读渲染器，展示标题、摘要、正文、区块、媒体和 SEO；原始 JSON 仅放入可折叠的“技术数据”区域。

### CMS-UI-004 — 编辑器响应式 CSS 已与现组件断开

- 严重度：Medium
- 类型：Responsive / CSS mismatch
- 位置：所有内容编辑页
- 证据：当前组件使用 `.content-editor__topbar`、`.content-editor__actions`、`.content-editor__layout`；`responsive.css:26-30,62-65,80` 仍控制旧的 `.editor-topbar`、`.editor-topbar__right`、`.editor-layout`。当前组件自身又在 `ContentEditorShell.vue:181` 于 1280 px 直接把三栏全部改成单栏。
- 实测：1440 px 为 `180px / 614px / 320px` 三栏；1280 px 已变成单栏；390 px 顶部操作区高度约 127 px，保存、预览、提交等全部换行堆叠。
- 影响：常见 1280 px 桌面和 1024 px 平板上，检查器被推到很长表单之后；移动端操作条占据过多首屏。
- 建议：移除旧选择器或迁移为当前命名；采用分阶段布局——宽屏三栏、中屏目录折叠 + 双栏、窄屏检查器抽屉/底部面板。

### CMS-UI-005 — “本地预览”名义与能力不匹配

- 严重度：Medium
- 类型：Invalid design / UX
- 位置：内容编辑器
- 证据：实际点击后只显示标题、摘要以及区块类型名称；`ContentEditorShell.vue:151-155` 仅输出 `<ol>` 和 `block.type`。
- 影响：用户会把它理解为页面预览，但它无法验证排版、内容、媒体、链接、模块顺序或移动端效果。
- 建议：短期改名为“内容摘要”并说明能力边界；长期复用公开页面渲染组件，提供桌面/移动预览。

### CMS-UI-006 — 未选区块时“区块”检查器是空白页

- 严重度：Medium
- 类型：Invalid design / UX
- 位置：内容编辑器右侧检查器
- 证据：实际点击“区块”后面板完全空白；`ContentEditorShell.vue:170-173` 始终启用标签，但只有 `selectedBlock` 存在时才渲染 `BlockInspector`，没有空状态。
- 影响：界面看似失效，用户不知道需要先选择区块。
- 建议：未选择时显示“请从页面组成中选择区块”，并提供焦点跳转；或者在无区块时禁用标签并给出 tooltip。

### CMS-UI-007 — 搜索与检查器状态的无障碍语义不足

- 严重度：Medium
- 类型：Accessibility
- 位置：草稿列表、内容编辑器
- 证据：GUI 的草稿搜索框在辅助功能树中仅为未命名的 `search text field`；`ContentListView.vue:72-75` 只有 placeholder。预览按钮没有 `aria-expanded` / `aria-controls`；检查器标签没有 `tablist`、`tab`、`tabpanel` 或 `aria-selected`。
- 影响：屏幕阅读器用户难以识别搜索用途及当前面板状态；placeholder 也会在输入后消失。
- 建议：增加可见或视觉隐藏的 `<label>`；补齐 disclosure 和 tabs 语义，并保持键盘切换行为。

### CMS-UI-008 — 字号过小，侧栏分组标题对比度不足

- 严重度：Medium
- 类型：Visual / Accessibility
- 位置：侧栏、内容目录、SEO 检查器、区块检查器、媒体和其他管理模块
- 证据：大量辅助文字使用 `0.52rem`–`0.68rem`，约 8.3–10.9 px；例如 `ContentOutline.vue:49-58`、`SeoInspector.vue:147-157`、`BlockInspector.vue:96-104`。侧栏分组标题为 `#617e83` / `#0b2933`，计算对比度约 3.50:1，同时字号只有 `0.56rem`。
- 影响：视觉上虽然精致紧凑，但长时间编辑吃力；侧栏分组标题未达到普通文本 4.5:1 的 AA 门槛。
- 建议：核心辅助文本底线设为 12 px，常规表单/列表文字至少 13–14 px；提升侧栏分组标题亮度或字号/字重。

### CMS-UI-009 — CSS token 和选择器存在失配/失效声明

- 严重度：Medium
- 类型：CSS architecture
- 证据：`--color-border` 在已发布列表、审核列表和编辑器活动标签中被使用但未定义；`ContentOutline.vue:52` 使用未定义的 `--admin-ink`。这些属性没有 fallback，浏览器会丢弃对应声明。全局 `editor.css` 与 `responsive.css` 仍保留大量旧 `.editor-*` 规则，而当前壳层改成 `.content-editor__*`。
- 影响：边框和文字颜色会默默退回浏览器默认值；后续维护者容易误以为响应式规则正在生效。
- 建议：统一到 `--admin-line` / `--admin-text` 等现存 token；删除或迁移已无消费者的旧规则，并给 token 加静态检查。

### CMS-UI-010 — 审核拒绝仍使用浏览器原生 prompt

- 严重度：Medium
- 类型：UX / Consistency
- 位置：内容审核
- 证据：`ContentReviewsView.vue:35-44` 使用 `window.prompt()` 收集拒绝原因。
- 影响：样式脱离 CMS、无法提供字段说明/字数限制/校验、移动端体验差，也不利于形成清晰的审核上下文。
- 建议：改为受控确认对话框，展示内容标题、版本、必填原因和取消/确认按钮；通过发布也应考虑二次确认。

### CMS-UI-011 — Admin 品牌标识不是规范公司 logo

- 严重度：Low
- 类型：Brand consistency
- 位置：侧栏和登录相关品牌区域
- 证据：`BrandMark.vue:8-11` 只用文字拼出 `AIRTEKPOWER`；品牌规范要求官方 logo 为图形标志与 wordmark 的固定组合，且当前没有获批的独立纯文字 logo 资产。
- 影响：作为后台产品名文字可以使用，但若被当作公司正式 logo，会造成品牌资产不一致。
- 建议：在获得官方组合标志资源后替换；在此之前把组件定位为产品文字标签，不宣称为官方 logo。

### CMS-UI-012 — 文案混入开发语境，空状态过于通用

- 严重度：Low
- 类型：Content design
- 位置：新建内容、审核空状态
- 证据：新建页使用“working draft”和“由开发种子创建的内容”等开发术语；审核空状态继承“创建或导入记录后会显示在这里”，但审核项必须先提交审核才会出现。
- 影响：业务用户难以判断下一步；生产 UI 暴露内部实现词汇。
- 建议：统一为“工作草稿/编辑草稿”；生产环境隐藏开发种子说明；为审核队列传入专用描述“草稿提交审核后会显示在这里”。

## 建议修复顺序

1. 先处理 CMS-UI-001、002、003：它们会让内容不可达、产生非预期写入或无法完成核对。
2. 再处理 CMS-UI-004、005、006、010：让编辑和审核主流程在 GUI 中真正可用。
3. 随后清理 CMS-UI-007、008、009：建立字号、token、响应式和无障碍基线，避免继续堆积样式债。
4. 最后统一品牌资产和业务文案。
